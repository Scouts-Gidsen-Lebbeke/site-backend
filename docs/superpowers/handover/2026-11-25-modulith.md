## Decisions taken with the owner (don't reopen)

- Spring Modulith in one deployable, with boundaries enforced by a test. Multi-module Maven and plain package-by-feature were rejected.
- Modules reference each other **by ID only**, including `User` and `Branch`.
- `Branch` and `Role` definitions live in `organization`. Only user↔role assignment (`UserRole`) lives in `access`.
- `payment` owns a single `payment` table (`ownerType`, `ownerId`) and publishes events. The `PaymentService<T>` inheritance goes away.
- Flyway is added. `V1__baseline.sql` is the owner's prod schema dump. Prod has one extra unused table, `user_contacts`, which was left in place. Only `dev` and `prod` baseline an existing schema. `local` and `test` must start from an empty DB, so drop the local `application` DB once if it has old tables.
- Groepsadmin:
  - The membership request (`LidAanvraag`) endpoint is public, so an event listener may call it, but it must be idempotent.
  - All other Groepsadmin calls stay in the admin-triggered sync endpoints, made with the admin's token.
  - No service account is possible.
- `shop` is parked: its entities move as-is, with no payment integration. A Shopify-like shop is a future project.
- The branch staff list moves out of the legacy branch controller. The owner accepted this API change, and it now happens in the people step (see Plan 2 decisions).
- REST contract otherwise stable.

## Calls made by Claude (in the spec, open to correction)

- `RoleLevel` goes to `shared.security`. Two SPIs live in `shared`: `UserLevelProvider` (implemented by `access` eventually) and `DefaultSenderProvider` (implemented by organization).
- Module internals use these sub-packages: `web`, `application`, `domain`. The root package is the public API.
  - Each module has a `<Name>Module.kt` with `@ApplicationModule(allowedDependencies = [...])`.
  - Without that file, a dependency on a legacy package goes unnoticed. This was a review finding.
- `ModularityTest.STRICT_MODULES` grows per module (now `shared`, `setting`, `news`, `organization`, `access`, `calendar`, `shop`). Legacy layer packages are tolerated until they're empty. The filter fails on violations whose source is a strict module, on cycles through a strict module, and on messages with unrecognised wording.
- `.claude/rules/testing.md` is binding, so there are no `@ApplicationModuleTest` or `@MockitoBean` per-class contexts. Module behaviour is tested via `@IntegrationTest` controller tests. `PersistedUsers` (test, `shared/util`) saves admin users and users without roles.
- Package moves were done with a script that rewrites package lines and imports. Watch for three things:
  - star imports
  - keywords mistaken for declarations
  - stale classes in `target/`, so run `mvn clean` after moves
- The event publication registry (`spring-modulith-starter-jpa`) arrives with the payment plan.
- Rollout order after plan 1:

  2. calendar + shop (done, plan 3)
  3. people

## Plan 2 decisions (open to owner correction)

- Legacy packages may use `organization` and `access` internals (tolerated), to keep the PR small. Chosen by the owner.
- `Address`, `AddressDTO`, `AddressRepository` and `Sex` live in `shared`, not `people`. Organization (strict) cannot depend on legacy code.
- The branch-staff API change moved to the people step. Staff listings need user data and `access` has no people API yet. `GET /branches/{id}` still embeds `staff`.
- `User.level` is a read-only `@Formula` over `user_role` and `role` until the people step.
- Role deletion is a synchronous event: `organization` publishes `RoleDeleting(roleId)`, `access` deletes the assignments in the same transaction. An after-commit listener would hit the `user_role.role_id` FK.
- No `OrganizationApi` yet. Legacy belcotax and certificate code keeps using `OrganizationProvider`.

## Plan 3 notes

- `BranchSummary` and `BranchApi.findSummaries` (in the `organization` root package) are available for later steps. The membership and activity DTOs will need them to embed branch `id`, `name` and `image` without touching the `Branch` entity.
- `shop` is extracted as parked: entities only, `allowedDependencies = ["shared"]`. `Shop` and `ShopOrder` inline the `Payable` and `Payment` fields, and `ShopOrder.user` is now `userId`. `Payable` and `Payment` stay in `entity/` for the legacy registrable and membership code until the payment step.
- PR note: the nested branch object in calendar responses now has OpenAPI schema name `BranchSummary` (was `BranchBase`). The JSON is unchanged (`id`, `name`, `image`).

## Behaviour changes to put in the plan 2 PR description

- `DELETE /user-roles/{id}` is now `DELETE /user-roles/role/{roleId}/user/{username}`. The old one always returned 404 after the ID-only change.
- `RoleController`, `ExternalFunctionController` and `UserRoleController` are now `@RestController`. Void and body endpoints used to return 500 on view resolution.
- The role assignment endpoints are transactional. In external mode a Groepsadmin failure now rolls back the local assignment (before, a retry hit "already has this role" while Groepsadmin lacked it).
